# מערכת רכזים – מעקב מרפאות, ביקורים ולידים

אתר סטטי (ללא build וללא התקנות). הנתונים וההתחברות ב-Supabase, והקוד כאן מורכב ממודולים קטנים (ES modules).

## מבנה התיקיות

```
index.html            מעטפת הדף: כותרת, אזור תוכן, ניווט, וטעינת הסקריפטים
css/
  tokens.css          צבעים ומשתני עיצוב (כולל מצב כהה)
  base.css            איפוס, טיפוגרפיה, כפתורים, שדות, כותרת וניווט תחתון
  components.css      כרטיסים, תגיות, טבלאות, רשימות, צ'יפים
  screens.css         סגנונות ייעודיים למסכים (דשבורד, לידים)
js/
  main.js             נקודת הכניסה: חיווט בלבד, בלי לוגיקה
  config.js           קבועים: חיבור, שמות קפיטציות, ספים, רשימות ברירת מחדל
  core/               תשתית: מצב (state), אירועים (events), מתווך (bus), עזרי DOM, ישיבת משתמש (session)
  utils/              פונקציות טהורות: עיצוב טקסט ותאריכים (format), בדיקות תקינות (validate), לוח (clipboard)
  api/                כל התקשורת עם Supabase: auth, loaders, visitsApi, leadsApi, clinicsApi, settingsApi, logApi, mappers
  domain/             לוגיקה עסקית טהורה: permissions (מי רואה מה), metrics (חישובים), checklist
  exports/            ייצוא לאקסל (ביקורים, לידים)
  ui/
    router.js         בחירת המסך לציור ומעבר בין מסכים
    components/       חלקי תצוגה קטנים וחוזרים (pill, card, capTable, tabs, listItem, formFields...)
    screens/          מסך לכל קובץ: home, clinics, clinicDetail, visits, visitForm, visitDetail, leads, admin, account, login
tests/run.mjs         בדיקות אוטומטיות מקצה לקצה מול שרת מדומה
```

## עקרונות

1. **כל שכבה מכירה רק את מה שמתחתיה.** מסך (ui) קורא ללוגיקה (domain) ולשרת (api), אבל לוגיקה ושרת לא מכירים מסכים.
   `domain` ו-`utils` הן פונקציות טהורות: מקבלות נתונים ומחזירות תוצאה, בלי לגעת בדף או בשרת.
2. **מסך = קובץ** שמייצא `render()` (מחזיר HTML) ו-`handlers` (הפעולות של המסך).
3. **אירועים מוצהרים ב-HTML**, לא מוצמדים בקוד:
   `data-act` (לחיצה), `data-chg` (שינוי ערך), `data-inp` (הקלדה), `data-enter` (Enter בשדה).
   הערך הוא שם פונקציה ב-`handlers` של אחד המסכים. שם כפול בין מסכים גורם לשגיאה באתחול.
4. **אבטחה:** כל טקסט שמגיע ממשתמש או מבסיס הנתונים עובר `esc()` לפני הכנסה ל-HTML. ההרשאות האמיתיות נאכפות בבסיס הנתונים (RLS),
   ובדיקות `permissions.js` נועדו רק להסתיר כפתורים.
5. **אין מידע אישי ביומן השינויים.** (ת.ז, טלפון ושמות לידים לא נרשמים ב-`logChange`.)

## איך מוסיפים מסך חדש
1. ליצור `js/ui/screens/myScreen.js` שמייצא `render()` ו-`handlers`.
2. להוסיף אותו ל-`SCREENS` ב-`js/ui/router.js`.
3. לרשום את ה-`handlers` שלו ב-`js/main.js` (הרשימה ב-`registerAllHandlers`).
4. להוסיף לשונית ב-`js/ui/components/tabs.js` (`TAB_DEFS`).

## איך מוסיפים קומפוננטה
קובץ ב-`js/ui/components/` שמייצא פונקציה שמקבלת נתונים ומחזירה מחרוזת HTML. בלי גישה ל-`ui` או ל-`store` אלא אם אין ברירה.
קומפוננטה שחוזרת בשני מסכים לפחות שייכת לשם. קומפוננטה של מסך אחד נשארת באותו קובץ.

## איך משנים כלל עסקי
- ספים ומספרים (70% מהיעד, 20 ימים ללא ביקור, ספי גודל מרפאה): `js/config.js`, וספי הגודל גם במסך הניהול.
- חישוב מאזן, אחוז מהיעד, מרפאות בפיגור: `js/domain/metrics.js`.
- מי רואה ומי עורך: `js/domain/permissions.js` **וגם** מדיניות ה-RLS בבסיס הנתונים. חייבים לעדכן את שניהם.

## בדיקות
```
node tests/run.mjs
```
מריץ את כל המסכים לכל משתמש, ובודק זרימות מרכזיות (כניסה, ביקורים, לידים, הרשאות, ייצוא). אינו נוגע בשרת האמיתי.
