## מבנה הקוד

### קבצים בריפו
```
index.html             כל האפליקציה: HTML, CSS ו-JS (כ-220KB)
manifest.webmanifest   הגדרות PWA (שם, צבעים, אייקונים, RTL)
sw.js                  Service worker – "רשת קודם", עותק שמור רק כשאין רשת
icon-180/192/512.png   אייקונים; icon-maskable-512.png לאנדרואיד
README.md              המסמך הזה
```

### המודולים בתוך `index.html`
הקובץ אחד, אבל הקוד בתוכו בנוי ממודולים נפרדים. כל מודול מתחיל בשורת סימון כמו
`/* ===== js/api/leadsApi.js ===== */`, ומודולים מייבאים זה מזה בעזרת `__req('js/…')`.
לחיפוש מודול מחפשים בקובץ את השם שלו.

```
js/config.js            קבועים: חיבור ל-Supabase, קפיטציות, ספים, ברירות מחדל, סטטוסי לידים
js/core/                תשתית: state, events (data-act/data-chg…), bus, dom, session
js/api/                 כל התקשורת עם Supabase: auth, client, loaders, clinicsApi, visitsApi,
                        leadsApi, settingsApi, logApi, mappers
js/domain/              לוגיקה טהורה: capitation, pace (קצב גיוס), metrics, permissions, checklist
js/exports/             ייצוא לאקסל: visitsExcel, leadsExcel, workbook
js/ui/components/       קומפוננטות: brand, card, collapsible, capTable, dayTable, liveCard,
                        paceCard, paceChart, pill, statRows, tabs, visitItem, formFields, listItem
js/ui/screens/          מסכים: home, clinics, clinicDetail, clinicEditForm, visits, visitForm,
                        leads, leadForm, admin, account, login
js/ui/router.js         בחירת מסך (SCREENS), ציור, ניווט אחורה
js/main.js              נקודת הכניסה: חיווט בלבד
```

### עקרונות
1. **כל שכבה מכירה רק את מה שמתחתיה:** `ui` ← `domain` / `api` ← `core` / `utils`.
2. **מסך הוא מודול** שמייצא `render()`, שמחזיר HTML, ו-`handlers`, שמכיל את הפעולות של המסך.
3. **אירועים מוגדרים ב-HTML:** `data-act` ללחיצה, `data-chg` לשינוי ערך, `data-inp` להקלדה ו-`data-enter` ל-Enter.
   הערך הוא שם פונקציה ב-`handlers`. אסור ששני מסכים ישתמשו באותו שם.
4. **אבטחה:** כל טקסט שמגיע ממשתמש או מבסיס הנתונים עובר `esc()` לפני שהוא נכנס ל-HTML.
5. **פרטיות:** ת"ז, טלפון ושמות לידים לא נרשמים ביומן השינויים (`logChange`).

### הוספת מסך חדש
1. מוסיפים מודול `js/ui/screens/myScreen.js` שמייצא `render()` ו-`handlers`.
2. מוסיפים אותו ל-`SCREENS` ב-`js/ui/router.js`.
3. רושמים את ה-`handlers` שלו ב-`registerAllHandlers` ב-`js/main.js`.
4. מוסיפים לשונית ל-`TAB_DEFS` ב-`js/ui/components/tabs.js`. אם המסך מיועד למנהל בלבד, מוסיפים `adminOnly: true`.

## עדכון יומי של מצטרפים

- **מקור הנתונים:** קובץ המצטרפים היומי שמגיע ל-Drive או ל-Gmail.
- **מה מריץ:** משימה מתוזמנת יומית של Claude שקוראת את הקובץ וקוראת ל-`ingest_live_joiners()`.
- **לאן זה הולך:** כל הרצה נרשמת ב-`live_joiners_log`. טריגר `live_daily_from_log` מעדכן את `live_joiners_daily` ואת `clinics.live_j`.
- **חישוב סך המצטרפים:** מרפאות **ועוד מאגר מבוטחים** (`pool`), מול סכום יעדי המרפאות.
- **התרעה:** אם הנתון ישן מ-7 ימים (`LIVE_STALE_DAYS`), מסך הבית מסמן שהעדכון האוטומטי נתקע.

### קישור ישיר מתוך הודעה
`?go=followups` פותח את מסך הלידים מסונן ל"המשך טיפול" (גם אחרי מסך הכניסה). הקוד: `js/core/deeplink.js`, מופעל מ-`startSession`. כדי להוסיף יעד, מוסיפים ערך ל-`LINKS`.

### איך זה עובד
```
pg_cron ──(כל דקה)──► wa_invoke('due')     ──► Edge Function wa-reminders?mode=due
pg_cron ──(05:00, 06:00 UTC)► wa_invoke('digest') ──► wa-reminders?mode=digest
                                                     (שולח רק כשבישראל 08:00, עובד בשעון חורף ובשעון קיץ)
```
- **אימות:** הפונקציה נפרסה בלי JWT, ובודקת כותרת `x-cron-key` מול סוד `wa_cron_key` ב-Vault.
- **מניעת כפילויות:** לכל שליחה יש `ref_key` ייחודי ב-`notify_log` (`lead:<id>:<followup_at>` או `digest:<profile>:<date>`). שינוי מועד הטיפול של ליד יוצר תזכורת חדשה.
- **רכז בלי מספר:** השליחה נרשמת ביומן כ-`no_phone` ולא נשלחת.

### קוד הפונקציה (`wa-reminders`, נמצאת ב-Supabase)
```
index.ts      כניסה, אימות, בחירת מצב: due | digest | check
config.ts     קריאת wa_config מ-settings, ו-WA_TOKEN מסודות
db.ts         שאילתות: לידים לטיפול, אנשים וטלפונים, יומן שליחות
whatsapp.ts   שליחת תבנית ל-Meta ובדיקת חיבור
reminders.ts  תזכורת לרכז
digest.ts     סיכום יומי
time.ts       עזרי שעון ישראל
```

## פריסה ועדכון גרסה

1. מעדכנים את `index.html` (או קובץ אחר) בריפו: GitHub ← Add file ← Upload files ← Commit.

3. בגלל אסטרטגיית "רשת קודם" ב-`sw.js`, המשתמשים מקבלים את הגרסה החדשה בכניסה הבאה בלי לנקות מטמון.
